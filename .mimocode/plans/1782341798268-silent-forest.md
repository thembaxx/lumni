# Fix all `suggestCanonicalClasses` Tailwind CSS IntelliSense warnings

## Summary

The `tailwindCSS.lint.suggestCanonicalClasses` rule from Tailwind CSS IntelliSense VS Code extension flags class names not in their most optimal/canonical form. The codebase has **~270+ warnings** across ~70 files in 3 main categories.

---

## Category 1: Old bracket variable syntax → paren syntax (HIGHEST IMPACT, ~234 occurrences, ~70 files)

Tailwind CSS v4 changed the arbitrary value syntax for CSS variables from square brackets `[--var]` to parentheses `(--var)`. Also, `[var(--x)]` should be simplified to `(--x)`.

**Pattern A** — `bg-[--system-accent]` → `bg-(--system-accent)` (~230 occurrences)
**Pattern B** — `bg-[var(--system-accent)]` → `bg-(--system-accent)` (~4 occurrences)

### Approach

- Use `rg` to find all `[--` patterns in className strings and replace `[--` with `(--` in the class attribute context
- For the `var()` variants, replace `[var(--X)]` with `(--X)`
- This is a **safe mechanical replacement** — same visual output, just canonical syntax

## NOT changing (intentional arbitrary values)

These patterns use arbitrary values intentionally and have no standard Tailwind equivalent:

- **Arbitrary spacing with px** (`w-[100px]`, `min-h-[250px]`, etc.) — custom design tokens, no standard scale value
- **`bg-[oklch(52%_0.18_146)]`** — custom accent color not in Tailwind palette
- **`active:scale-[0.96]`** — fine-grained micro-interaction values
- **`border-[1.5px]`, `border-[2.5px]`, `border-[6px]`, `border-[3px]`** — no standard Tailwind equivalent for non-integer border widths
- **`bottom-[-5px]`** — offset value
- **`p-[3px]`** — custom compact spacing
- **`h-[16.6px]`, `h-[14px]`, `w-[28px]`, `w-[24px]`** — switch component precise dimensions
