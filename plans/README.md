### Rejected / not planned this pass

- **`motionEase` vs `iOSEase` consolidation**: The two easing constants in `animation.ts` serve different purposes — `motionEase` is an overshoot curve, `iOSEase` is a clean ease-out. Both have legitimate use cases. Documenting the distinction is sufficient; merging them would lose the overshoot behavior that some components depend on. Flag for the next design system audit.
- **View transition `root` animation**: The `::view-transition-old(root)` and `new(root)` at `globals.css:698-703` use `ease-out` (CSS keyword) with short durations (80ms/120ms). These are within budget and the curve is correct for a crossfade. No change needed.
- **Vaul drawer configuration**: Drawers use Vaul's built-in spring animation. Vaul's spring configs are not accessible from CSS and are the library's responsibility. If the drawer feels wrong, file a Vaul issue.
- **Sonner toast configuration**: Toasts use Sonner's built-in animations. Sonner's config API is available but the default animations are already well-tuned. No change needed.
